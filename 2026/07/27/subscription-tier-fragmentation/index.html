订阅档位正在碎片化:当"买哪个"比"用哪个"更难

#定价策略 #订阅制 #消费决策

2026 年 7 月,ChatGPT 的付费档位增加到了六个:Free、Go $8、Plus $20、Pro Codex $100、Pro Max $200、Business $20/席,外加 Enterprise。而在两年前,这个数字是两个。这不是孤例——Claude、Cursor、Copilot、Kimi 都在做同样的事。模型能力在收敛,定价结构却在发散。

// 核心观点摘要
  • 档位数量暴涨:ChatGPT 从 2 档增至 7 档;Kimi 有 5 档;Cursor、Copilot 各 5 档。
  • 关键变化:原统一 $120 的 ChatGPT Pro 拆为 $100(5× Plus) 与 $200(20× + 1M 上下文);新增 $8 的 Go 档但含广告。
  • 碎片化的动因:能力趋同后,价格歧视成为主要的利润提取手段。
  • 对用户的代价:决策成本转嫁给消费者——你需要先精确知道自己的用量,才能选对档位。
  • 务实对策:先测用量,再选档;警惕"看起来只贵一点"的升级诱导。

一、七个档位的 ChatGPT

先看事实。2026 年 7 月的 ChatGPT 价目表:

档位 价格 关键限制
Free $0 基础模型,限量
Go $8 消息量高于 Free,但含广告、无 Codex、无高强度推理
Plus $20 日常高额度 + Codex 云任务 30–150 个 / 5h
Pro Codex $100 5× Plus 额度
Pro Max $200 20× 额度 + 1M 上下文
Business $20/席(年付) $25 月付,最少 2 人
Enterprise 定制 —

其中三处是近期变化:Pro 自 2026 年 4 月 9 日起从统一 $120 拆成 $100 / $200 两档;Go 档从 $6 涨到 $8;Business 改为年付 $20、月付 $25。

最值得注意的是 Go 档含广告——这是主流 AI 助手第一次把广告写进付费订阅。付了钱仍然看广告,这个定位在消费电子史上通常预示着市场进入了”用价格分层榨取剩余”的阶段。

二、这不是 OpenAI 独有

横向看,整个行业在同步碎片化:

  • Claude:Free / Pro $20 / Max 5x $100 / Max 20x $200 / Team / Enterprise
  • Cursor:Hobby / Pro $20 / Pro+ $60 / Ultra $200 / Teams $40
  • GitHub Copilot:Free / Pro $10 / Pro+ $39 / Max $100 / Business $19 / Enterprise $39
  • Kimi:Free / Moderato $19 / Allegretto $39 / Allegro $99 / Vivace $199
  • Trae:Free / Lite $3 / Pro $10 / Pro+ $30 / Ultra $100

一个规律浮现出来:几乎每家都在 $20 和 $200 之间塞进 2–3 个中间档。这个价格带的填充不是偶然——它对应着”愿意多付但不想付满额”的最大人群。

三、为什么现在开始碎片化

其一,能力趋同逼出了价格竞争。 当前沿收敛让顶部模型的差距压到几十 ELO,厂商无法再靠”我们更强”定价,只能靠”你用多少付多少”来提取剩余价值。多档位本质上是价格歧视(经济学中性词):让高用量用户付更多,同时不吓跑低用量用户。

其二,成本结构允许精细切分。 推理成本随用量线性变化,这与传统软件”边际成本近零”截然不同。既然成本是线性的,定价自然也倾向于线性分层。

其三,竞争对手的档位互相锚定。 ChatGPT 的 $100 Pro Codex 档几乎是对 Claude Max 5x($100)的直接应答;Trae 的 $10 Pro 对标 Cursor 的 $20 Pro。档位在互相复制,格局趋于对称。

四、代价:决策成本转嫁给了用户

碎片化对厂商是收入优化,对用户是认知负担。

要选对档位,你必须先回答一个多数人答不上来的问题:**我每月到底用多少?**这不是”我每天用两小时”能回答的——同样两小时,写代码和聊天的 token 消耗能差十倍;同一个模型,effort 档位不同成本又差三倍。

于是出现一个尴尬局面:厂商用精确的分层收费,面对的是一群对自己用量毫无概念的用户。结果通常是两种错配:

  • 买贵了:为了”保险”直接上顶配,额度长期用不满。以 Claude Max 20x 为例,轻度用户的实际单价可能是重度用户的十倍以上。
  • 买亏了:选了便宜档,月中撞额度墙,工作被打断——而时间损失往往超过省下的几十美元。

五、务实对策

1. 先测用量,再选档。
用一两周的实际使用估算 token 量级,再对照各档额度。本站选购助手的「用量自测」就是为此设计的——填几个典型场景的频次,算出月用量,再看哪档刚好覆盖。实测中经常出现的结果是:按粗略档位该买 $15 的,精确算完发现 $3 的就够。

2. 优先选”刚好够用”而非”绰绰有余”。
额度利用率决定实际单价。用满 60–100% 的档位,单位成本最低;用不到 25% 的档位,你在为空气付费。

3. 警惕”只贵一点”的升级诱导。
$100 到 $200 看起来只是”翻倍”,但如果你的用量只需要 5× 而非 20×,多付的 $100 每月全是沉没成本。档位间的价格差不是能力差,是额度差——先确认你缺的是能力还是额度。

4. 别忽略按量付费。
如果你的使用是阶段性爆发(几天猛用、之后闲置),订阅制的固定月费和 5 小时窗口对你都是不利结构。直接用 API 按量付费,闲置期一分钱不花。这条选项常被忽视,因为它不在任何厂商的”推荐档位”里。

六、一个预测

档位碎片化大概率会继续,直到出现两种力量之一:

  • 监管介入:订阅制的”限额不透明”已经在多个市场引起注意。当”5× 额度”无法被用户验证时,它接近于一种不可核实的承诺。
  • 用量计价成为主流:如果按量付费的工具链足够好用(账单可预测、有硬性上限),订阅制的存在意义会被削弱。

在那之前,看懂档位表本身就是一项省钱技能。这也是本站维护模型天梯性价比板块的原因——把各家的档位、额度制度、折算单价放在同一张表里对比,是目前对抗信息不对称最直接的办法。

  • 各档"额度"的官方口径多为相对倍数(如"5× Plus"),缺乏可独立验证的绝对值;本站的 token 量级为估算,仅供横向比较。
