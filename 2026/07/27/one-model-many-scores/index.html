一个模型,N 个分数:当 effort 和编排模式让榜单失去唯一解

#基准测试 #推理强度 #成本优化

“Claude Opus 5 拿了 61 分”——这句话在 2026 年已经不完整了。同一个模型,换一个推理强度设置,分数和账单都会变;换一种编排模式,甚至可能变成另一个量级。**”一个模型对应一个分数”的隐含假设,正在崩塌。**

// 核心观点摘要
  • 同一模型多个条目:Artificial Analysis 榜单上,GPT-5.6 Sol (max) 59 分与 Sol (xhigh) 58 分是两个独立条目。
  • effort 不改单价,改 token 消耗:Claude Opus 5 的 low→max 五档,同一任务成本差约 3 倍。
  • 并行编排是第二个变量:GPT-5.6 Sol 的 Ultra 模式把任务分给多个子代理,Terminal-Bench 2.1 从 88.8% 升到 91.9%,但一次运行相当于数次调用。
  • 更高不等于更好:FrontierCode 数据显示 Opus 5 在 medium effort 就达到编程峰值,再往上收益递减。
  • 实践建议:先调 effort,再考虑换模型——多数任务用 medium 就够,账单可能直接减半。

一、榜单上的”同名不同分”

打开 Artificial Analysis 的智能指数榜,你会看到一些看似重复的条目:

条目 分数
Claude Opus 5(Adaptive Reasoning, Max Effort) 61
Claude Fable 5(Adaptive Reasoning, Max Effort, Opus 4.8 Fallback) 60
GPT-5.6 Sol(max) 59
GPT-5.6 Sol(xhigh) 58

最后两行是同一个模型。AA 把不同推理强度当作不同的被测对象分别列出——这是诚实的做法,因为它们确实是不同的东西:消耗的 token 不同、花的钱不同、答得也不一样好。

而当媒体或社区引用”GPT-5.6 Sol 得了 59 分”时,几乎没人会附上”在 max effort 下”这个前提。分数被剥离了它的成本背景,这正是当下模型讨论最大的信息损耗。

二、两个独立的”堆算力”旋钮

要理解为什么会这样,得先分清 2026 年模型有两种加深思考的方式:

旋钮一:推理强度(effort)

Claude Opus 5 提供五档:low / medium / high / xhigh / max。它不改变每 token 的单价——$5/$25 对所有档位一样——改变的是模型愿意为一道题花多少 token 去规划、自检、返工。

代价是实打实的:在 Frontier-Bench 上,low 到 max 的每次成本差约 3 倍;high 大约是 medium 的两倍。

旋钮二:并行编排(orchestration)

GPT-5.6 Sol 的 Ultra 模式走的是另一条路:不是把一条思维链拉长,而是把难题分派给多个并行子代理,各自处理再汇总。

效果显著——Terminal-Bench 2.1 从基础 Sol 的 88.8% 提升到 **91.9%**。但代价同样直接:Ultra 模式没有单独标价,每个子代理各自生成和消耗 token,一次 Ultra 运行相当于好几次普通 Sol 调用。

这两个旋钮可以叠加。于是”一个模型”实际上是一个分数-成本的连续谱,而不是一个点。

三、最反直觉的发现:更高 ≠ 更好

如果”调到最高档”总是更强,那事情还简单。但数据不支持这个直觉。

Anthropic 官方明确建议广泛使用 low 和 medium 档,称它们”以一小部分 token 消耗和延迟提供良好结果,且优于早期 Opus 模型的同档设置”。

FrontierCode 基准的实测更直接:Claude Opus 5 在 medium effort 达到编程峰值(主集 53.4%、扩展集 63.6%),再往上是收益递减。

为什么会这样?一个合理的解释是:过度思考会引入噪声。模型在简单任务上花更多 token 反复推翻自己的正确答案,反而可能偏离。这与人类做题时”想太多改错答案”的经验高度一致。

四、对使用者的三条实践

1. 把 effort 当成第一个省钱旋钮,而不是最后一个。
大多数人的优化顺序是”贵了就换便宜模型”,但换模型意味着换能力,而调低 effort 往往不损失质量。先试试把默认档从 high 降到 medium,观察输出质量——如果没退步,你的账单立刻减半。

2. 按任务分配 effort,而不是全局一个设置。
补全、格式转换、常规改代码 → low/medium 足够;架构设计、疑难 bug、长程重构 → 才值得上 high/max。把 effort 当作按任务下注的筹码。

3. 读榜单时先问”哪一档”。
看到某个惊人的分数,先确认它是在什么设置下跑的。本站模型天梯的成本图已经加了红色 MAX EFFORT 标记——那些数字是成本上限,不是你的日常开销。

五、更大的问题:基准测试的可比性正在瓦解

这件事的深层影响是:当同一个模型能产生一族分数时,跨模型比较变得更难了。

模型 A 的 max 档对上模型 B 的 medium 档,比的到底是什么?如果 A 用了三倍的钱换来 2 分优势,这算赢吗?

这也是为什么本站的天梯坚持把”同卷不同价“的成本图与能力榜并列——脱离成本的能力排名,在 2026 年已经是一种误导。当行业进入前沿收敛阶段,能力差距被压缩到几个百分点,而成本差距却能到 27 倍时,后者才是真正需要看清的维度。

// 风险提示
  • 各家 effort 档位的命名与行为不统一(Anthropic 五档、OpenAI 的 xhigh/max/ultra 模式),跨厂商横向对比"同档位"没有严格意义。
  • 文中成本倍数关系来自公开基准与厂商说明,实际任务上的差异取决于任务类型,可能显著偏离。
  • Ultra 类并行编排模式的实际账单波动很大,生产环境部署前建议先做小规模成本实测。
