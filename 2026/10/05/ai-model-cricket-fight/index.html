自己办一场 AI 斗蛐蛐:七个回合,一个下午测出谁更适合你

#评测方法 #模型选型 #入门

榜单告诉你”谁平均更强”,但你关心的是”谁在我的活儿上更强“。这两件事经常对不上:同一个模型换个工具壳、换个推理强度,分数就能差出一截;公开题目还可能早被模型背过。

最靠谱的办法是自己出题、自己比。不需要写评测框架,也不需要花钱——准备几个模型的免费额度、一个浏览器、一个下午就够。下面是一套七回合的斗蛐蛐流程,每回合给一道能直接复制的题、一个看得见的判分标准。

开打之前:四条规矩

1. 同条件。同一道题、同样的推理强度、每次开新对话(关掉记忆功能),在同一类工具里跑。
2. 盲评。把输出复制出来,标成甲乙丙,让朋友打乱顺序再给你看——你知道是哪家写的,打分就会偏。
3. 每题跑两次。模型有随机性,一次赢不算赢;两次结果差很大,本身就是一个扣分项。
4. 只计看得见的结果。能打开、能运行、能数出来的才算分,"感觉写得更有深度"不算。

为什么要自己出题?公开题目会进训练数据,模型可能是”背出来”的。LiveBench 这类榜单定期换新题,就是为了对付这个问题(论文)。你自己编的题,模型一定没见过。

打分统一用三档:0 = 没做到,1 = 部分做到,2 = 完全做到。比十分制好判,吵不起来。

第一回合:做网站(看一次出活的完整度)

把下面这段原样发给每个模型:

做一个单文件 HTML 页面,是一家虚构奶茶店「半糖」的点单页。要求:
1. 不用任何外部库和图片链接,所有样式和脚本写在同一个文件里
2. 手机宽度下单列排布,电脑宽度下三列
3. 右上角有亮色 / 暗色切换按钮,刷新后记住选择
4. 至少 6 款饮品,每款可选甜度(全糖 / 半糖 / 无糖)
5. 点"加入"后,购物车角标数字 +1,底部显示总价
6. 购物车可以删除单项,总价同步更新

怎么判:存成 .html 双击打开,对着六条逐条点。每条做到得 1 分,满分 6。再把浏览器窗口拉窄,看手机布局有没有乱。

这回合看什么:能不能一次把多条要求都落实。弱一点的模型通常前三条做得漂亮,第 5、6 条的交互要么没写,要么点了没反应。

第二回合:前端性能(看写出来的代码快不快)

做一个单文件 HTML 页面:一张 10,000 行的表格(列:编号、姓名、城市、金额,数据用脚本随机生成),
上方一个搜索框,输入时实时筛选。搜索框监听 input 事件,不要加防抖。不用外部库。

怎么判:打开页面,按 F12 打开控制台,粘贴下面这段回车,记下毫秒数,每个页面测三次取中间值:

const box = document.querySelector('input');
const t0 = performance.now();
box.value = '7';
box.dispatchEvent(new Event('input', { bubbles: true }));
await new Promise(r => requestAnimationFrame(() => setTimeout(r)));
console.log('筛选耗时', Math.round(performance.now() - t0), 'ms');

想再多一项,可以用 Chrome 开发者工具自带的 Lighthouse 给第一回合的页面跑一次性能分。

这回合看什么:差距通常很明显——有的模型每敲一个字就重建一万行 DOM,有的只切换显示或做了虚拟滚动。数字差几倍到几十倍,不用争。

第三回合:改代码(用”隐藏测试”判对错)

发给模型的只有这一段:

下面这个 Python 函数有 bug,请修好它,只输出修好的函数。

def merge(intervals):
    """合并重叠区间,首尾相接也算重叠。
    例:[(1,3),(2,6),(8,10)] → [(1,6),(8,10)]"""
    result = []
    for start, end in intervals:
        if result and start < result[-1][1]:
            result[-1] = (result[-1][0], end)
        else:
            result.append((start, end))
    return result

怎么判:下面这组测试不要给模型看。把模型的答案和它放进同一个文件,运行一下,看通过几个:

cases = [
    ([], []),
    ([(1, 3), (2, 6), (8, 10)], [(1, 6), (8, 10)]),
    ([(8, 10), (1, 3), (2, 6)], [(1, 6), (8, 10)]),   # 输入乱序
    ([(1, 3), (3, 5)], [(1, 5)]),                     # 首尾相接
    ([(1, 10), (2, 3)], [(1, 10)]),                   # 大区间包住小区间
    ([(1, 4), (0, 2), (3, 5)], [(0, 5)]),
    ([(5, 5)], [(5, 5)]),
]
ok = 0
for inp, want in cases:
    try:
        ok += merge(list(inp)) == want
    except Exception:
        pass
print(f"{ok}/{len(cases)}")

原函数藏了三个 bug:没先排序、相接时用了 < 而不是 <=、合并时没取较大的终点。原版只能过 3/7,全修好才是 7/7。只修了题干例子能看出来的那个,是这回合最常见的失分方式。

第四回合:工具使用(看它会不会自己动手验证)

这回合要在能调工具的环境里跑:Claude Code、Codex、Cursor、Trae 都行,或者网页版里打开联网搜索。两道题:

4a. 自己跑测试。把第三回合的原函数存成 merge.py,测试代码存成 test_merge.py,放进一个空文件夹,然后说:

这个文件夹里的测试没通过,请修好 merge.py。不许修改 test_merge.py。

怎么判:看过程,不只看结果。运行了测试 +1,改完又跑了一次确认再 +1,没碰测试文件 +1,最终全通过 +1,满分 4。偷改测试文件让它”通过”的,这回合直接 0 分。

4b. 该查就查。

Python 当前最新的正式版本号是多少?给出你的信息来源链接。

怎么判:自己打开 python.org 对答案。用了搜索、答对、给了真链接得 2 分;没搜、凭记忆报了个旧版本得 0 分。这道题测的不是知识,是它知不知道自己的知识会过期。

第五回合:特定语言(测你真正要用的那门)

这回合按你自己的需要换题,下面给两个例子。

5a. 中文语感。

把下面这段改得像中国人自然说话,意思不变:
"该功能的实现使得用户能够在进行文件上传的操作的过程中获得关于进度的实时的反馈。"

怎么判:几个模型的答案打乱顺序给家人看,问”哪句最像人话”。还嫌长、还堆着”的”的,排后面。

5b. 小众编程语言。假设你写 Rust:

用 Rust 写一个函数,统计一段文本里出现次数最多的 3 个单词(忽略大小写和标点),
返回 Vec<(String, usize)>,并写一个 main 演示。只用标准库。

怎么判:粘进官方的 Rust Playground 点运行。一次编译通过得 2 分;把报错贴回去改一轮能过得 1 分;两轮还过不了得 0 分。换成你常用的语言也是一样的判法——编译器是最公正的裁判。

第六回合:多模态(看它是真看懂了还是在编)

6a. 小票对账。拍一张超市小票,发给模型:

把这张小票上的每一项商品和价格列成表格,最后算出合计,并和小票上印的合计对比。

怎么判:数它列对了几项(名称和价格都对才算)。最后合计跟小票对得上加 2 分。看不清就说看不清的,比硬编一个数字强——编出小票上没有的商品直接扣 2 分。

6b. 截图复刻。随便截一个网页的局部(比如某个登录框),发给模型:”用单文件 HTML 复刻这个界面”。打开后和原图左右对比,布局、配色、文字三项各给 0/1/2。

想再玩得花一点,可以学 Simon Willison 的经典题”画一只骑自行车的鹈鹕(SVG)”(他的历次结果)——它测的是空间理解,结果一眼就能看出高下。

第七回合:执行力和理解力(看它听不听话、会不会多想一步)

7a. 约束清单。

写一段介绍你最喜欢的季节的文字,要求:
1. 正好 3 段
2. 每段不超过 60 个字
3. 全文不能出现"的"字
4. 第二段必须提到一种食物
5. 最后一句以问号结尾
6. 不要用任何标题、列表或加粗

怎么判:六条逐条数,满分 6。第 3 条最难,也最拉开差距——很多模型写着写着就忘了。

7b. 陷阱题。两道各发一次:

请用 100 字总结下面这篇文章的核心观点。

(什么都不附。)

鲁迅为什么在《红楼梦》里安排林黛玉进贾府?

怎么判:第一题,指出”你没给文章”的得 2 分,凭空编一段总结的得 0 分。第二题,纠正前提(《红楼梦》是曹雪芹写的)得 2 分,顺着编下去的得 0 分。这两道题测的是理解力里最值钱的那部分:发现问题本身有问题。

记分:别只看总分

把结果填进一张表:

回合 满分 模型甲 模型乙 模型丙
1 做网站 6
2 前端性能 毫秒,越低越好
3 改代码 7
4 工具使用 4 + 2
5 特定语言 2 + 2
6 多模态 按项数 + 6
7 执行与理解 6 + 4

然后只圈出跟你有关的回合。你主要写前端,就看 1、2、4;你主要处理文档和表格,就看 5、6、7。总分第一的模型,在你的场景里未必第一——这正是自己测的意义。

几个容易踩的坑:

  • 别拿免费版和付费版比。同一个名字,免费档常常用的是更低的推理强度,详见你买的不是模型,是”让它想多久”
  • 别拿网页版和编程工具比。同一个模型换个外壳,工具回合能差出一大截,原理见harness 入门
  • 走中转站的先验货。如果你用的是第三方中转 API,先确认拿到的是真模型:中转站验货指南
  • 题目别公开。你的题一旦发到网上,迟早会被模型背下来。想长期用,就每隔几个月换一批

结语

榜单是体检报告,斗蛐蛐是试驾。前者告诉你车的参数,后者告诉你开着顺不顺手。七个回合跑下来大约两三个小时,得到的结论只对你有效——但这恰好就是你要的。

想先看看大家公认的排名,再挑几个来试驾,可以从模型天梯开始;免费额度去哪里领,看那一页的羊毛速查框。
