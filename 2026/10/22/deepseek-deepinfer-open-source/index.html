DeepSeek 开源了自家“后厨”:你用不上,但它会改变你买到的 DeepSeek

#开源 #DeepSeek #推理引擎 #API 中转 #基准测试

10 月下旬,DeepSeek 在 GitHub 上放出了 DeepInfer——它自己线上服务用的那套推理引擎。几天之内收获近两万颗星,中文圈的标题大多是”DeepSeek 又开源了”。

先说结论:绝大多数读者自己用不上它,但它会实实在在地影响你从第三方平台买到的 DeepSeek 是什么成色。这篇讲清楚三件事:开源了什么、为什么你家放不下、它对”同一个模型各家跑分不一样”这个老问题意味着什么。

// 一句话摘要
  • 开源了什么:推理引擎 DeepInfer(Apache 2.0),配套 1017 版模型权重(MIT)、提示词编码库 deepseek-recipe(MIT)和一套评测脚本。目前只支持 V4.1 Flash 1017 一个模型。
  • 你家放不下:光权重文件就有 510GB,一张 RTX 5090 只有 32GB 显存;何况 DeepInfer 只支持英伟达 SM100 数据中心卡和华为昇腾 950。
  • 真正受益的是托管商:云平台和中转站可以直接用官方同款内核与调度,第三方 DeepSeek 的质量有望更接近官方。但 KV 缓存、预填充/生成分离、负载均衡这三块官方没给,还得各家自己补。
  • 最有意思的功能:批次无关推理和确定性采样——同样的输入,不管和谁挤在一批,结果都一样。这让"复现官方跑分"第一次变得可操作。
  • 对你的影响:用官方 API 的人,账单不变;用第三方的人,以后可以多问一句"你用的什么引擎、哪个版本"。

一、这次到底开源了什么

“开源”这个词这次涵盖了好几样东西,性质完全不同:

组件 许可 是什么 普通人能拿来干什么
DeepSeek V4.1 Flash 1017 权重 MIT 模型本体,10-17 发布 基本干不了,太大(见下节)
DeepInfer Apache 2.0 官方线上推理引擎,本次的主角 同上,且只支持数据中心卡
deepseek-recipe MIT 把各种 API 格式的请求编码成 DeepSeek 提示词、再把输出解析回来的工具库 开发者做适配时省事
评测脚本 Apache 2.0(随 DeepInfer) AIME 2026、HLE、GPQA Diamond 三套离线评测 有算力的人能复现官方分数
昇腾版矩阵运算 / 通信库 MIT 等 9 月底先行放出的 DeepGEMM-Ascend、DeepEP-Ascend 给华为昇腾平台用

DeepInfer 的 README 写得很坦白:它最初主要基于开源引擎 vLLM 打造,另外参考了 SGLang 和 TensorRT-LLM;这次放出的是”离线推理”部分,支持的功能包括 DeepSeek 自家的一整套优化内核、注意力与专家并行、草稿加速解码、结构化输出等。

同样坦白的是缺什么。README 明确列出,要组成完整的推理服务,还缺三样:

  1. KV 缓存系统(多轮对话、长上下文复用的关键)
  2. 预填充与生成分离部署(README 说大部分引擎功能已经实现,但没给完整方案)
  3. 数据并行副本之间的负载均衡

换句话说,DeepSeek 开放的是”灶台和刀工”,不是整间”后厨”。

二、为什么你家放不下这口锅

上一篇《显卡还要涨多久》刚算过,RTX 5090 在美国网店的最低价已经到了 7,998 美元。拿它来对照这次开源的东西:

想在家跑 1017 版,先过这几道门槛
权重体积来自 Hugging Face 上的官方模型文件合计;显卡数量和金额是本站的纯算术换算,只为直观对比,不代表这样真能跑起来——还没算 KV 缓存的显存,DeepInfer 也不支持消费级显卡。

2,100 亿输出 token 是什么概念?按本站天梯里 Artificial Analysis 的实测,1017 版跑完一整套智能指数测试大约花 445 美元。对个人和小团队来说,”自己部署更省钱”在这个量级上完全不成立;DeepSeek 官方 API 谷时每百万输出 token 0.60 美元的价格,本身就已经是它自家这套引擎规模化之后的结果。

三、真正受益的是谁:托管商,以及间接的你

既然个人用不上,开源给谁?答案是云平台、推理服务商和中转站——那些本来就在用 DeepSeek 开源权重对外卖 API 的人。

以前它们拿到权重之后,要自己在 vLLM、SGLang 之类的通用引擎上做适配。DeepSeek 的模型结构越来越特殊(1017 的模型页列出了滑动窗口加压缩稀疏注意力、两级索引器、多模态编码器等一长串组件),各家自己的实现和官方之间难免有出入。

这种出入不是假想的。2025 年 9 月,月之暗面专门开源了一个 K2 Vendor Verifier,起因就是用户反馈:同一个 Kimi K2,在不同托管商那里的工具调用表现差异明显。月之暗面在说明里提醒,用户挑服务商时往往只看延迟和价格,忽略了更隐蔽的精度差异。

DeepInfer 等于把”官方怎么跑”的答案直接摆了出来。对第三方来说,可以照着做;对用户来说,以后有了一个可以追问的标准:”你们跑 DeepSeek 用的是不是官方引擎?是哪个版本的权重?”

但别高估它:

  • 只支持英伟达 SM100 和昇腾 950 两种硬件。用其他卡的托管商,仍然只能参考,不能直接搬。
  • 缺的那三样(KV 缓存、分离部署、负载均衡)恰恰是线上服务的核心,各家自己补的部分,依然可能和官方不一样。
  • 托管商为了省钱可能做额外的量化或截断,这和用什么引擎无关。

所以准确的说法是:第三方 DeepSeek 的成色”有条件变得更接近官方”,而不是”从此和官方一样”。中转站的验货方法,本站的《中转站选购与验货》仍然适用。

四、最值得关注的功能:让跑分可以复现

DeepInfer 的功能清单里,有两项对普通读者的意义比”快多少”更大:批次无关推理和确定性采样。

先说问题是什么。很多人以为,大模型在温度设为 0 时应该每次输出一样,但实际上并不是。Thinking Machines 的研究员 Horace He 在 2025 年 9 月的一篇长文里拆解过原因:线上服务会把很多人的请求拼成一批一起算,而批次的大小和组成会微妙地改变计算的数值顺序,于是同一个问题,在服务器忙的时候和闲的时候,可能得到不同的答案。

DeepInfer 把这个变成了一个开关:开启批次无关模式后,模型结果不受同批其他请求影响;再固定随机种子,同样的输入就能得到完全一样的输出(README 注明这两项目前只在英伟达平台上可用)。

这和本站一直在追的问题直接相关。我们在《一个模型,N 个分数》和《当考卷泄题成为常态》里反复写过:同一个模型,换个跑法、换个平台,分数可以差很多;而厂商自报的分数,外人很难核对。

DeepInfer 这次把这两样拼在了一起——确定性推理 + 随引擎附带的评测脚本(AIME 2026 每题采样 32 次、HLE 全量 2,500 题、GPQA Diamond 每题 8 次)。理论上,任何有算力的第三方都可以按同样的设置跑一遍,看能不能复现模型页上的数字。

// 但要分清:自报分和第三方实测是两回事

1017 的模型页列了一张对比表(和 Kimi K3、GLM-5.3、GPT-5.6 Sol、Opus 5 比),用的都是 DeepSeek 自己挑的测试和设置。本站天梯不用厂商自报分,只收第三方实测:截至 10-22,1017 版在 Artificial Analysis 智能指数为 45(旧版 39),在 LiveBench 2.0 为 79.2,综合排第 12。可复现是好事,但复现的仍是厂商选的考卷。

五、一个行业信号:英伟达和昇腾两条腿

DeepInfer 的 README 把华为昇腾 950 和英伟达 SM100 并列写为支持硬件;9 月底,DeepSeek 还单独放出了昇腾版的矩阵运算库 DeepGEMM-Ascend 和通信库 DeepEP-Ascend。

从工程角度看,这说明 DeepSeek 的线上服务至少在两种完全不同的硬件上都做了深度优化。对国内用户的直接含义是:跑在国产算力上的 DeepSeek 服务,也能用到官方同款的引擎,不必因为硬件不同而打折扣。

至于这对供应链、对芯片厂商意味着什么,已经超出本站”帮读者把 AI 的账算清楚”的范围,这里不展开,也不构成任何投资判断。

六、读者该怎么用这条消息

  • 用官方 App 或 API 的:什么都不用变。开源不改变官方价格,本站天梯的性价比表照常有效。
  • 用第三方平台或中转站的:可以开始问”用的什么引擎、哪个版本的权重(是不是 1017)”。答不上来或者含糊其辞的,用验货方法测一测,尤其是工具调用和结构化输出这两项。
  • 企业想私有化部署的:DeepInfer 降低了”跑对”的难度,但没降低”跑起来”的门槛。先确认手里有 SM100 或昇腾 950 集群,再评估补齐 KV 缓存、分离部署和负载均衡的工程量。
  • 想在家跑本地模型的:这次的东西不适合你。参考上一篇的显卡价格,再看看小尺寸的开源模型。

  • "16 张 5090""2,100 亿 token"是本站按公开数字做的算术换算,只为直观对比,不是部署方案。
