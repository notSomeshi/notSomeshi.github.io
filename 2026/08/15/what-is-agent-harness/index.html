同一个模型,换个壳分数差 24 分:harness 入门

#Agent #评测方法 #harness

你花时间挑了半天模型,最后选了榜单第一。然后发现别人用着更差的模型,干活比你顺。

这事有个具体的解释,而且能量化。

北京大学与奇元科技在 2026 年做了一项叫 Harness-Bench 的研究:固定任务、固定模型,只换外面那层执行框架,跑了 5,194 条执行轨迹。结果是——

同样的模型、同样的 106 个任务,只换 harness
柱长按最高分(NanoBot 76.2%)归一为 100%。8 个模型后端 × 6 个 harness,共 5,194 条执行轨迹的聚合分。
NanoBot最高 76.2%
OpenClaw最低 52.4%

来源:Harness-Bench: Measuring Harness Effects across Models in Realistic Agent Workflows(Yilun Yao 等,北京大学 / 奇元科技)。快照 2026-08-15。

23.8 个百分点。 模型没换,题没换,换的只是”外面那层东西”。

那层东西是什么

论文给了一个挺完整的定义:harness 是管理上下文、工具、状态、约束、权限、追踪与恢复的系统层,负责把模型的输出变成真正能执行的动作。

一个公式概括:

Agent = Model + Harness

模型负责”想”,harness 负责把想法变成事。具体到日常,harness 在替你做这些决定:

  • 给模型看什么 —— 上下文里塞哪些文件、塞多少、什么时候截断
  • 给模型什么工具 —— 能不能读文件、能不能跑命令、工具描述怎么写
  • 出错了怎么办 —— 是重试、换路子,还是直接把报错甩给你
  • 什么时候停 —— 循环几轮算够、什么情况判定失败
  • 哪些事要问你 —— 删文件要不要确认、能不能自己 git push

你平时用的 Claude Code、Cursor、Codex、Trae,本质上都是 harness。它们背后往往可以接同一批模型——所以”用哪个工具”这个选择,和”用哪个模型”是两个独立的维度。

一个反直觉的发现

如果只记一条,记这个:

模型越弱,换 harness 时的分数波动越大;模型越强,对 harness 差异越不敏感。

这是 Harness-Bench 的结论之一:强模型后端的跨 harness 方差更低,弱模型则”对周围的执行基质更敏感”。

意味着什么?

如果你在用旗舰模型,harness 选择的收益相对有限——强模型自己就能扛过糟糕的上下文管理和粗糙的工具描述。

如果你在用便宜模型(开源自部署、国产平价 API、免费额度),harness 才是你最该优化的地方。同样一个中等模型,配好 harness 和配差 harness,差距可能比你升级到下一档模型还大。

这个结论对预算敏感的人尤其重要:换工具通常比换模型便宜,而且在你这个档位上收益更大。

一句话版本:预算充足的人挑模型,预算有限的人挑 harness。后者的性价比曲线更陡。

但要小心谁在给你看数字

这里有个陷阱。

Harness 的对比数据,很多是 harness 厂商自己发的。而 FutureAGI 的一篇分析注意到一个规律:同一个模型在 SWE-bench Pro 上,独立标准化评测(Scale AI 的 SEAL 实验室)跑出的分数,低于三家厂商对比表里的全部数字。

这不难理解——厂商用自家 harness 时会调到最优,对照组则往往是默认配置。你看到的”我们比他们高 5 分”里,有多少是 harness 真实差距,有多少是调参投入差距,外人无从分辨。

另外,Epoch AI 的一项研究发现同一模型在 SWE-bench Verified 上,**仅因脚手架不同,分数就能从 62.3% 变到 70.2%**。这也提示了另一件事:当你看到某个模型”刷新 SOTA”时,那个数字里有一部分不属于模型。

关于评测数字为什么越来越不能直接信,之前那篇文章讲得更细。

这对你选工具意味着什么

第一,别把模型排名当工具排名。 本站天梯页排的是模型能力,Agent 平台板块比的是 harness——这是两张表,不能互相替代。榜单第一的模型装进糟糕的 harness 里,可能不如第五名装进好 harness。

第二,评估工具时,试你自己的真实任务。 harness 的差距体现在长任务、多轮工具调用、出错恢复这些地方,而不是”写个快排”。跑十个玩具题看不出区别,跑一个真实重构立刻见分晓。

第三,注意 harness 也在变。 它是软件,会更新。你半年前对某个工具的判断,可能已经过期了——LangChain 曾在 Terminal-Bench 上只改系统提示、工具和中间件,分数就涨了 13.7 分,模型一行没动。

第四,论文给业界的建议同样适用于你:能力应该按**”模型–harness 配置”**这个组合来报告,而不是记在模型头上。所以下次有人跟你说”某某模型很强”,值得追问一句:你在什么 harness 里用的?

2026 年上半年,行业的注意力几乎全在模型参数和榜单名次上。到了下半年,”harness”这个词突然到处都是——因为大家发现,把同一个模型的能力真正兑现出来的那部分工程,长期被算进了模型的功劳簿。

模型决定了天花板,harness 决定你能摸到多高。
