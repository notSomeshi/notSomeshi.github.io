同一个模型,四种价格:2026 年的账单正在变复杂

#成本优化 #定价策略 #入门

三个月前,选模型只需要看一个数字:每百万 token 多少钱。

现在同一个 GPT-5.6 Sol,你可能付 $2.50、**$5.00** 或 $10.00 的输入价——取决于你走的是 Batch、标准还是 Fast。DeepSeek 还准备按你调用的时间点收不同的钱。

这篇把 2026 年 8 月还在生效的几种计费模式拉平了讲清楚,以及什么时候该用哪个。

// 一句话摘要
  • OpenAI 现在有四档:Batch / Flex(五折)、标准、Fast(2 倍)。Fast 是 7 月 30 日由 Priority processing 改名而来。
  • Anthropic 的杠杆是缓存:命中只要 0.1×;Batch 五折;Opus 的 Fast 模式 2 倍。
  • DeepSeek 缓存命中约 1/120($0.435 → $0.003625),是全场最激进的缓存折扣。
  • 峰谷计费仍未生效:DeepSeek 官方口径是"即将实施、生效日待公告",峰时将按 2 倍计。
  • 省钱顺序:缓存 > 批处理 > 降 effort > 换模型。多数人跳过前两步直接换模型,顺序反了。

一、OpenAI:四档,极差 4 倍

GPT-5.6 Sol 的四种价格
每百万 token 输入价。柱长按 Fast 模式($10)归一。同一个模型,同样的输出质量。
Fast优先处理 $10.002× 标准
标准默认 $5.00基准
Flex弹性排队 $2.50五折
Batch异步批处理 $2.50五折

输出价同比例:Fast $60 / 标准 $30 / Batch 与 Flex $15。Luna 与 Terra 是同样的四档结构。

OpenAI 官方定价页。「Priority processing 于 2026-07-30 更名为 Fast mode」。快照 2026-08-04。

什么时候用哪档:

  • Batch —— 不赶时间的批量任务(翻译、摘要、打标、离线评测)。异步提交,五折。这是最容易被忽略的省钱手段,很多人明明在跑离线任务却用标准档。
  • Flex —— 同样五折,但走弹性排队,适合能容忍延迟波动的在线任务。
  • 标准 —— 交互式场景的默认选择。
  • Fast —— 只有当延迟直接影响体验或收入时才值得。2 倍价格买的是排队优先级,不是更好的答案。

二、Anthropic:杠杆在缓存

Anthropic 没有 Flex,但把缓存做得很细:

操作 倍率 说明
缓存命中 0.1× 只要标准输入价的十分之一
5 分钟缓存写入 1.25× 缓存有效 5 分钟
1 小时缓存写入 2× 缓存有效 1 小时
Batch 批处理 0.5× 输入输出都五折
Fast 模式(仅 Opus 5 / 4.8) 2× $10/$50

关键在于回本次数:5 分钟缓存写入 1.25×、命中 0.1×,所以一次命中就回本;1 小时缓存写入 2×,两次命中回本。系统提示词、长文档、多轮对话历史这类反复出现的内容,不做缓存等于白扔钱。

另外两条容易漏的:

  • 1M 上下文按标准价计,不加价(4.6 及以后机型)。90 万 token 的请求与 9 千 token 单价相同。
  • 4.7 及以后机型换了新分词器,同样的文字约多出 30% token。跨代比价时只看单价会低估实际账单。

三、DeepSeek:缓存折扣最激进,峰谷仍未落地

模型 缓存未命中 缓存命中 输出
deepseek-v4-pro $0.435 $0.003625 $0.87
deepseek-v4-flash $0.14 $0.0028 $0.28

缓存命中价约为未命中的 1/120。 这个折扣力度远超其他家(Anthropic 是 1/10,OpenAI 是 1/10),意味着在 DeepSeek 上把提示词结构设计好的收益极大。

峰谷计费:目前仍未生效。 官方文档的措辞是”即将实施,生效日期以官方公告为准”,峰时(北京时间 9:00–12:00、14:00–18:00)将按 2 倍计。Semafor 8 月 3 日报道称 DeepSeek 在竞争压力下暂停了这套动态定价的落地。

⚠ 网上有不少文章称”峰谷计费已于 7 月实行”,与官方文档不符。以官方定价页为准。

四、省钱的正确顺序

多数人的第一反应是”换个便宜模型”,但那通常是最后一步:

四个省钱杠杆,按性价比排序
典型可省比例。前两步不改变输出质量,后两步会。
① 用好缓存
−90%
命中部分的输入价,质量不变
② 能异步就 Batch
−50%
输入输出都五折,质量不变
③ 降一档 effort
约 −60%
low→max 成本差约 3 倍,质量略降
④ 换更便宜的模型
可达 −95%
幅度最大,但要重新验证质量

缓存与 Batch 倍率见各家官方定价页(Anthropic · OpenAI · DeepSeek);effort 成本差见 Anthropic 官方说明。快照 2026-08-04。

前两步不改变输出质量,应该先做。 缓存和 Batch 是纯粹的工程配置问题,省下来的钱没有任何代价。

第三步降 effort 有代价但通常很小——Anthropic 官方也建议日常用 low/medium。

第四步换模型幅度最大(从 $93.8/分 换到 $3.4/分 是 96%),但需要重新验证质量。要换的话,先看《把 15 个模型的真实账单拉齐之后》确认目标档位。

五、一个提醒

计费模式变复杂本身是个信号:厂商开始用价格歧视来切分需求——愿意等的人少付钱,赶时间的人多付钱。这在成熟行业(航空、电力、云计算)是常态,说明 AI 推理正在从”稀缺品”变成”公用事业”。

对用户来说,这意味着账单越来越取决于你怎么调用,而不只是调用了谁。同一个模型、同样的任务,配置得当和随手调用之间可以差好几倍。

// 风险提示
  • 本文为 2026-08-04 快照,倍率与价格均取自各家官方定价页。计费规则变动频繁(Fast mode 刚在 7-30 更名、峰谷计费状态反复),以官网当期页面为准。
  • "典型可省比例"为按官方倍率推算的上限:缓存 −90% 只作用于命中部分,实际节省取决于命中率;effort 的 3 倍差是 Anthropic 对 Opus 5 的口径,其他模型不同。
  • Batch 与 Flex 有延迟代价,不适合交互式场景;缓存有有效期,低频调用可能写入成本大于收益。
  • 本文不构成任何投资或采购建议。
