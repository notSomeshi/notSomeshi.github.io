中转站选购与验货:怎么测出模型被"降智"或货不对板

#安全 #API 中转 #模型验证

一个不太舒服的数字:2026 年 3 月,CISPA 对”影子 API”端点做了一轮审计,45.83% 未通过模型身份验证——你付钱买的是旗舰模型,拿到的不是。基准分差最高达 47 分。

而这件事最难受的地方在于:它不会报错。 返回格式一样,model 字段照样写着旗舰名,响应也像模像样。你唯一能感觉到的,只是”最近好像笨了点”。

这篇讲两件事:怎么用两百次请求把它验出来,以及买之前该看什么。

一、先分清两种坑法

整体替换(model substitution):每一个请求都换成便宜模型。这种最好抓——测一次就现形。

路由稀释(routing dilution):只把其中一部分请求偷偷路由给便宜模型,其余照常。

第二种才是主流,也是为什么”我试了几次感觉没问题”完全不可靠。假设 30% 的请求被稀释,你随手问三五个问题,大概率全落在正常的那 70% 里。

这两个概念来自新加坡与清华团队的 IRIS 论文(2026 年 7 月),它专门研究怎么在只能看到返回文本的前提下审计网关。

二、简单测试:让它”随机”一下

核心原理一句话:大模型没法真随机,而每个模型不随机的方式各不相同。

这就是指纹。让模型反复回答”从 1 到 100 里随便挑个数”,它会形成一个高度偏斜且稳定的分布:

  • 42 被严重超额选中(《银河系漫游指南》的锅)
  • 两位质数扎堆——37、47、73 出现率远高于均匀分布,因为它们”对人类而言显得随机”
  • 整体上,中位答案分布只携带约 1.0 bit 熵,而真正均匀分布是 6.64 bit

这个偏斜是模型权重的产物,换个模型就变。

怎么做

用一组固定探针(比如”1–100 随机数””随便说个颜色””抛硬币”),在参考端点与待测端点上各跑一遍,比较两边的答案分布。

轻量版配置足够用了:

项 值
探针 8 组
每组采样 25 次
请求总数 ≈ 200
temperature 1.0(必须,否则没有分布)
max_tokens 16
成本 约 $0.005

怎么判读

用 Jensen-Shannon 散度衡量两个分布的距离,参考刻度:

答案分布的 JS 散度:三个参考点
柱长按最大值(0.46)归一为 100%。散度越大,越可能不是同一个模型。
同模型自比基线噪声 0.14
同模型跨供应商量化/kernel 差异 0.23
确实是两个模型 0.46

来源:Tosea.ai,Fingerprinting Models with Random Numbers。快照 2026-08-20。

判定门槛:≤0.25 视为匹配,0.25–0.35 存疑,>0.35 判为不匹配。

注意中间那根柱子——同一个模型在不同正规供应商之间也有 0.23 的距离。IRIS 的实测同样发现,15 对供应商里有 14 对可区分,来源是量化精度与推理 kernel 的差异。所以别把”有差异”直接等同于”被骗了”,要看差异有多大。

顺手能看的几个辅助信号

跑这轮测试时,顺便记下这些:

  • prompt token 数异常膨胀 → 中转站往你的请求里插了隐藏系统提示
  • completion token 填充 → 输出被凑长度(可能在按 token 计费上做手脚)
  • split-half 不稳定(前一半与后一半样本的分布明显不同) → 多后端路由,正是稀释的迹象
  • 响应快得不合理且完全一致 → 在偷偷做缓存

三、一个必须知道的限制

指纹可以被伪造。 有研究(arXiv 2606.16100)专门指出这种攻击:供应商可以拿便宜模型微调,让它模仿贵模型的行为特征,从而骗过用户侧的指纹检测。

所以这套方法的定位要摆正:它能高效抓住懒惰的骗子,抓不住认真的骗子。 对绝大多数以省成本为目的的中转站,它够用;但它不是密码学证明。

补充一点尺度感:IRIS 在 32 次查询后对 17 个商业模型的归属判定准确率能到 0.98,并能把路由比例估到 ±0.04 以内——所以样本量比单次测试重要得多。

四、买之前看什么

价格是最强的信号。安全研究把这个市场称作"暗 token 经济":未授权代理以低于官方定价最多 90% 转售 Claude、GPT、Gemini 的访问权。这个折扣不可能来自运营效率——它来自欺诈账号、池化账号,或者根本就没打算给你真模型。便宜三成可以谈,便宜九成一定有问题。

比”降智”严重得多的三件事

质量缩水只是最轻的后果。中转站在你和模型之间,能做的事远不止换个模型:

一、你的所有 prompt 和响应都会经过它,而且可能被完整记录。 这些日志的下游用途包括欺诈和模型蒸馏。你贴进去的代码、客户数据、内部文档,都在里面。

二、密钥可以被被动窃取。 明文流量里的 API key 与凭据会被顺手收走,而且下游应用行为完全正常,极难察觉。

三、工具调用载荷可以被改写。 这条对用编程 Agent 的人最致命——比如把一个正常的包安装 URL 换成攻击者控制的脚本,你的 Agent 就替攻击者执行了任意命令。你以为你在用 AI 写代码,实际上是在给它开后门。

务实的几条

  1. 别用中转站跑生产,也别喂敏感数据。 省下的钱和一次数据泄露不在一个量级。
  2. 先小额充值 + 跑一轮指纹测试,别一上来就买年付。不退款的中转站遍地都是。
  3. 给它单独的账号与密钥,和你的正式凭据完全隔离,并定期轮换。
  4. 周期性复测,而不是只测一次。 路由稀释是可以随时调的——今天干净不代表下个月干净。
  5. 优先考虑有官方定价页的正规平台。 本站性价比表里的 SCNet、硅基流动这类,价格、计费规则、限制条款都写在官方文档上,可核对、可追责——这和一个只有 Telegram 客服的中转站是两回事。

五、说到底

中转站这个生意存在,是因为官方渠道对国内用户确实有摩擦——支付、网络、账号,都是真实痛点。这篇不是劝你完全不用。

但要清楚自己在交换什么:你用可验证性换了价格。 那就至少把验证这一步补上——两百次请求、半分钱、十分钟,能把”我感觉最近变笨了”变成一个有数字的判断。

在一个近半数端点通不过身份验证的市场里,“感觉还行”不是一种质量保证。
