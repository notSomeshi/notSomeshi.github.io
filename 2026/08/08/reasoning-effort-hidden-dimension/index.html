你买的不是模型,是"让它想多久"

#推理强度 #成本结构 #评测方法

打开任何一份 AI 模型对比表,你会看到一列分数、一列价格。这个结构暗示了一件事:模型是个固定的东西,你买它,它给你确定的能力。

这个前提在推理模型时代已经不成立了。

以 Artificial Analysis 智能指数 v4.1.1 的实测数据为例,同一个 GPT-5.6 Luna,在不同推理强度下的得分是 27、34、39、47、50、52——最高档接近最低档的两倍。它们是同一个模型、同一套权重、同一个 API 端点,唯一的区别是你让它”想多久”。

换句话说:你买的不是一个模型,而是一条从便宜笨到昂贵聪明的连续曲线。而绝大多数对比表只截取了这条曲线上的一个点——通常还是最贵的那个点。

核心判断:推理强度(effort)是模型选型里被系统性忽略的第三个维度。忽略它会导致两类错误——按榜单的 max effort 分数做选型,却按默认档位使用(能力对不上);或者把所有任务都开到最高档,为不需要的思考付钱(成本对不上)。而研究显示,思考过头不只是浪费,还会主动损害准确率。

一、现象:一个模型,六个分数

先看数据。下面两条”阶梯”来自 AA 智能指数 v4.1.1 的公开榜单,同一模型的不同 effort 档位各自独立评测:

这张图里藏着两个结论。

第一个:Luna 开到最高档(52),恰好等于 Opus 5 开到最低档(52)。 两条路径能到达同一个能力点,但成本、延迟、失败模式完全不同。选型时如果只比”Opus 5 是 63 分、Luna 是 52 分”,你根本看不到这个交叉点的存在。

第二个:Opus 5 的 xhigh 与 max 得分完全相同,都是 63。 也就是说从 xhigh 再往上加算力,收益是零——但账单不是零。这就是边际收益递减最直白的证据。

二、机制:为什么曲线是这个形状

力量一:思考预算的收益曲线是凹的,而且会封顶

推理模型的”思考”消耗的是输出 token——也就是最贵的那一类。所以 effort 每上一档,成本上升是线性甚至超线性的,而分数上升越来越慢。

多项研究得出了一致结论:性能随思考 token 预算增加而提升,随后趋于平坦;超过某个阈值后,继续加预算带来的边际收益迅速衰减。上图里 Opus 5 从 high(61)到 xhigh(63)只涨 2 分,再到 max 涨 0 分,正是这条曲线的尾部。

值得注意的是,曲线的形状因模型而异。Opus 5 在 medium 档就已经拿到 59 分(最高分的 94%),而 Luna 在 medium 档只有 39 分(其最高分的 75%)。强模型的曲线更早饱和,弱模型更依赖长思考来补足。这意味着”开高一档”这个动作,对不同模型的性价比完全不同。

力量二:想得太多会主动损害准确率

这一条最反直觉,但证据相当明确。

学界的多项工作发现,超过某个阈值后,准确率不是持平而是下降——额外的推理在某些情况下会主动降低正确率。ACL 2026 的一项研究专门考察了模型在基础数学题上的”过度思考”现象:面对本该一步得出的问题,推理模型会生成冗长的自我怀疑与反复验算,反而把原本正确的答案推翻。

机制上这不难理解:更长的思维链意味着更多的中间步骤,每一步都是一次引入错误的机会;而模型缺乏”这题已经做对了,可以停了”的可靠判断力。在简单任务上开高 effort,是在花钱买风险。

这也解释了 Anthropic 的一个产品决策:较新的模型取消了手动设定思考预算,改为由模型自适应控制,只留一个 effort 参数来调节深度。把”想多久”的决定权从用户手里收回一部分,恰恰是因为用户很难判断该给多少。

力量三:榜单默认最高档,而你默认不是

第三条力量属于信息结构问题。

评测机构为了衡量模型的能力上限,普遍采用最高 effort 设置——AA 的成本页明确标注推理模型均取厂商披露的最高档。这在方法论上完全正确:比较上限才有可比性。

但用户在实际使用中,极少运行在最高档。IDE 插件、Agent 框架、聊天界面,默认档位通常是 medium 或 high;很多产品甚至根本不暴露这个参数。

于是形成了一道系统性的落差:你看到的排名是 max effort 下的,你得到的体验是默认档位下的。 对 Opus 5 这类早饱和的模型,落差只有 4 分(63 → 59);对 Luna 这类依赖长思考的模型,落差是 13 分(52 → 39)——同样的榜单,对不同模型的失真程度差了三倍多。

这一点也是本站在成本对照表上强制标注 MAX EFFORT 徽章的原因:不标清 effort 前提的成本数字,是没有意义的。

三、影响:三类使用者,三种错法

只看榜单选型的人:买到的能力比预期低

这是最常见的错法。看到”Opus 5 排第一”就选它,却在默认档位下使用——实际拿到的是 59 分而不是 63 分,却付着旗舰的价钱。

更糟的情况是反过来:看到某个便宜模型”分数只差一点”就选了它,而那个分数是 max effort 跑出来的,你的默认档位离它很远。Luna 的 52 分和 39 分之间,隔着的是”能不能完成任务”的分界线。

无脑开最高档的人:为不需要的思考付双倍

另一个极端同样常见,尤其是在企业环境里——“预算够,全开最高档,别出错”。

这个策略有三重代价:成本(输出 token 是最贵的)、延迟(思考时间直接体现为等待)、以及前面说过的准确率反噬。对于分类、格式转换、简单问答这类任务,高 effort 不仅没用,还可能把简单题做错。

做 Agent 的人:成本会以平方级爆炸

Agent 场景下这个问题被放大得最厉害。Agent 的每一轮循环都要调用模型,而循环次数本身又受模型质量影响——effort 调低导致单轮质量下降,可能反而需要更多轮次。

有研究比较了单 Agent 与多 Agent 系统在同等思考 token 预算下的表现,发现单 Agent 在多跳推理任务上反而更优。这提示了一个容易被忽略的事实:在固定预算下,把 token 花在”更深的思考”还是”更多的 Agent 协作”上,是一个需要实测的取舍,而不是”多 Agent 一定更强”。

方法论提示:本文引用的所有分数均为 AA 智能指数 v4.1.1 口径(2026-08-06 发布,该版本重算了全部模型分数)。跨版本的分数不可直接比较——引用任何评测数字前,务必确认是哪个版本、哪个 effort 档位。缺少这两个前提的分数对比,结论可能完全反向。

四、务实建议:把 effort 当成一个可调旋钮

第一,按任务难度分档,而不是按预算分档。

一个可操作的划分:

任务类型 建议档位 理由
分类、抽取、格式转换、改写 最低档 / 非推理模式 高档位无收益,且有过度思考风险
常规编码、文档问答、日常对话 medium 多数模型在此档已达上限的 90% 左右
复杂重构、多步推理、疑难调试 high 边际收益仍为正的区间
真正的硬问题(且允许长等待) xhigh / max 只在确认收益未封顶时使用

第二,亲手测一次你常用模型的饱和点。

拿你自己的 20 道真实任务,在 low / medium / high 三档各跑一遍,记录正确率与耗时。你大概率会发现某一档之后曲线就平了——那个点就是你的默认档位,而不是厂商或榜单替你选的那个。

第三,引用分数时永远带上两个前提。

任何一个模型分数,如果没有说明评测版本和effort 档位,它就不具备可比性。这不是学究,而是实用:v4.1.1 相对 v4.1 整体上移了 2–3 分,而 max 与 medium 之间又差 4–13 分——两个前提都不交代的话,误差范围足以覆盖大多数模型之间的真实差距。

推理强度这个维度之所以长期被忽略,是因为它打破了一个让人舒服的心智模型:模型是个名词,你选一个就完事了。

实际情况更接近于:模型是个动词。同一套权重,可以表现得像个 27 分的快速应答器,也可以表现得像个 52 分的深思者,取决于你愿意为这次调用付多少。而”付多少最划算”这个问题,没有通用答案——它取决于你的任务难度分布,而那个分布只有你自己知道。

下一次看到”某模型排名第几”时,值得多问一句:这是它开到几档时的成绩?我会开到几档?
