机器人和你,过验证码的次数一样多

有一组对照实验的结果,大概是这两年安全领域里最尴尬的数字。

苏黎世联邦理工的 Andreas Plesner 等人做了一件很朴素的事:让一个机器人和一群真人分别去过 reCAPTCHA v2,数各自需要几轮挑战才能通过。

机器人的中位数是 2 轮。人的中位数也是 2 轮。

均值上机器人 2.71、人 3.50,做 t 检验,p 值 0.11——没有统计学显著差异。作者在论文里的措辞很克制,但意思不含糊:这个结果”对图像验证码能准确区分人类与非人类用户这一传统认知提出了质疑”。

你可能会想,那是不是他们的机器人特别强。是挺强的——用微调过的 YOLOv8 做分割和分类,在 reCAPTCHA v2 的图像挑战上求解率 100%。但这不是重点。重点是下面这个数字。

真正决定你能不能过的,不是那张图

同一篇论文里还有一组对照:带上 cookie 和浏览历史去做题,通过所需的挑战中位数从 5 轮降到 2 轮,p 值 0.00,显著得毫无争议。

论文的解释是,”存在浏览历史或 cookie 时 reCAPTCHAv2 似乎更容易完成,大概是因为安全系统识别出了一个已有的可信用户”。

把这两组数据放一起,结论就出来了:

那张图不是考题,是申诉。系统在你看到图片之前就已经给你打过分了。图片出现,意味着分数不够高;点对了,只是把分数补回及格线。分数够高的人,压根看不到图。

这解释了一个很多人有过的困惑:为什么有时候点一下勾就过了,有时候要连点三轮红绿灯还被判错。不是题变难了,是你那次的分低了——换了网络、开了隐私模式、清了 cookie、或者用了个不常用的浏览器。

图这一层,确实早就失守了

顺着时间线看会更清楚这层防线是怎么一点点没的:

第三、四行才是这两年真正的变化。上海交大林云团队做的 Halligan,把”解验证码”这件事归约成了一个搜索问题:一套统一的提示词、一套描述验证码结构的元模型,然后交给视觉语言模型去搜。

它在 26 种视觉验证码、2,600 道题的基准上拿到 60.7%,和那些专门为某一种验证码训练的求解器打平;更关键的是,拿去野外跑 30 天,面对训练时从没见过的验证码,拿到 70.6%。覆盖的方案包括 reCAPTCHA v2、hCaptcha、GeeTest、Yandex、腾讯、Arkose、Amazon、百度。

过去破解一种验证码要单独立项,现在换一种验证码不用改代码。 防守方”换个新花样再撑一年”这条路,成本结构变了。

但”验证是不是机器人”这件事没有失效

这是最容易被误读的地方。图像谜题失守 ≠ 检测失效,因为判定的重心早就搬走了。你没看见的地方至少有这么几层:

网络层指纹。 IP 与 ASN 的声誉、TLS 握手指纹(JA3/JA4)、HTTP/2 的 SETTINGS 帧与 header 顺序。这些在 TCP 连接建立到第一个字节返回之间就完成了,和你的模型多聪明毫无关系——你还没机会展示智能,分就打完了。

浏览器指纹。 渲染栈、字体列表、时区与语言是否自洽、有没有自动化框架留下的痕迹。

行为方差。 这一层最反直觉:它看的不是”你做得对不对”,而是”你做得有多不稳定”。真人的鼠标轨迹是抖的,阅读时长是波动的,点击落点是不准的,偶尔还会犹豫和回退。机器人追求效率,于是表现为不自然的精确和过快的提交。

换句话说:人类的签名是"不精确"。一个把每个动作都做对、做快、做准的客户端,恰恰是最可疑的。这也是为什么"解题解得又快又对"本身就是一个可检测信号——大模型把延迟压到接近人类反应时间,消掉的正是这个破绽。

工作量证明。 干脆不判断你是谁,而是让你的设备算一会儿。它把成本从”人的注意力”转移到”设备的算力”,用计算而不是个人数据来换通行。

密码学与硬件证明。 Cloudflare Turnstile 这类方案直接绕开了”出题”这个动作本身。

维基百科的实测:从人人做题,到 2% 的人做题

抽象的层级不如一个真实迁移有说服力。

维基媒体基金会 2025 年 9 月启动试验,用 hCaptcha 替换自 2000 年代沿用至今的扭曲字母验证码。当时 Eric Mill、Kosta Harlan 与 Szymon Grabarczuk 在官方博客里给出的预期是,约 99.9% 的访客将完全不会看到谜题。

2026 年 5 月的第二篇复盘给出了实测口径:

我们的旧验证码系统的工作方式是挑战所有用户,寄希望于这个挑战对人类可做、对机器人困难。在 hCaptcha 的新方案里,系统只挑战可疑活动,因此极少有真人用户(我们估计约 2%)会真的收到视觉挑战。

两个数字都值得记:预期 0.1%,实测 2%——差了二十倍。这个落差本身说明”可疑”的判定线比设计者以为的更宽松。但即便如此,98% 的人再也不用做题了,而试验期内涉及 hCaptcha 的账号封禁率下降了 31%。

从”所有人做题”到”2% 的人做题”,这就是整个行业这几年发生的事,只不过多数网站没有写博客告诉你。

反转:它拦不住机器人,拦人倒是很在行

联合国大学校园计算中心那篇分析里有一句很扎眼的话:

验证码在阻止成熟机器人这件事上力不从心,却在阻止人类方面出奇地有效。

这不是俏皮话,是可测量的:

  • 文字验证码首次尝试失败率 8.66%;若区分大小写,接近 30%
  • 音频验证码的放弃率高达 50%
  • 估计有 15% 的网站用户因验证码的无障碍设计问题而失败
  • 全球约 13 亿人存在显著程度的残障
  • 一个注册表单把验证码换成隐形垃圾检测后,转化率从 48% 升到 64%(相对提升 33%)

把这几条并排看:一个安全措施,对攻击者的边际成本约等于零,对合法用户的流失率是两位数。这已经不是”防护力下降”的问题,是收益与代价倒挂了。

更根本的问题:题目本身可能问错了

即使把上面所有技术细节都解决,还有一个更麻烦的事实。

Cloudflare Radar 的数据显示,自动化请求已占 HTML 网页流量的 57.5%,人类只剩 42.5%。2026 年 6 月 3 日,Cloudflare CEO 宣布机器人流量首次超过人类——比他自己预计的 2027 年底提前了一年半。AI agent 请求同比增长超过 1,700%;在已验证的机器人请求里,Claude-User 以 11.3% 排第二,仅次于 GoogleBot 的 14.2%,是 GPTBot(5.8%)的近两倍。

注意 Claude-User 这个身份的性质:它不是爬虫,是用户让它去看的。

于是”人还是机器”这个二分开始失灵了。当我让一个 agent 替我去查资料、比价、填表,它到底算不算”我”?按旧口径,它是机器人,该拦;按实际意图,它是我授权的代理,拦了就是拦我。

这时候要问的已经不是”你是不是人”,而是”你是谁派来的、有没有被授权、行为受不受约束”。

于是行业在换一套东西:证明授权,而不是证明人性

这件事已经不是设想了,在落地。

由 Cloudflare 牵头的 Web Bot Auth 走的是这条路:基于 RFC 9421(HTTP 消息签名),每个 agent 持有一把 Ed25519 私钥,给每一个 HTTP 请求签名,通过 Signature-Agent 头带上身份,公钥放在可查的目录里。站点验签,就知道来的到底是不是它自称的那个 agent——User-Agent 伪造这条路直接被封死。

有意思的是它的推进节奏:IETF 已经成立了 WebBotAuth 工作组,但截至 2026 年 8 月 12 日,工作组还没有任何已采纳的文档,只有个人草案;而 Cloudflare、AWS WAF、Akamai、HUMAN、Vercel 已经在生产环境验签,拿它决定哪些 agent 能进站。Visa TAP 与 Mastercard Agent Pay 也把它作为身份基础。

标准还没定,产品先上了。 这通常意味着需求真实且紧迫。

对站点来说,这是第一次可以有选择地放行 agent,而不是”要么全放要么全拦”。对 agent 来说,这意味着以后能不能上网,取决于你有没有一个可追溯、可撤销的身份——而不是你的视觉模型有多强。

这和之前那篇里写的供应权问题是同一件事的两面:当访问权可以被精确地授予和撤销时,它就成了一种筹码。

防守方怎么说

公平起见,把另一边的说法也放上。

hCaptcha 在 2026 年 2 月的一篇博客里主张自己依然有效,理由有三条:视觉语言模型与人类之间仍存在”细微或明显的性能差距”,这些差距”在未来数年内仍将对检测有用”;它的挑战是”持续移动的靶子”,一旦某类挑战的自动化通过率上升就迅速弃用或更新;以及部署其企业版的站点在 2026 年录得”攻击总量下降 70–90%“。

但这篇博客有两处明显的空白:它没有给出任何针对视觉语言模型或浏览器 agent 的求解率数字;而那条 70–90% 的核心主张,既没有方法论说明,也没有独立验证。防守方公布"攻击量下降"而不公布"求解率",本身是一种选择——攻击量下降也可能只是攻击者转向了成本更低的目标。

值得注意的是,hCaptcha 的三条理由里,最硬的那条恰恰不是关于图的:”迅速弃用被攻破的挑战”说的是运营节奏,不是题目难度。这其实印证了本文开头那个判断——图片是可替换的耗材,判定在别处。

所以,对你意味着什么

如果你是普通用户:你过不了验证码,多半不是因为你眼神不好,而是因为你的会话看起来太干净——新设备、隐私模式、VPN、清过 cookie。想少做题,保持浏览环境的一致性比认真找红绿灯有用得多。这也解释了为什么隐私保护得越好的人,验证码做得越多——这是个真实存在、且没被认真对待的代价。

如果你在做产品:如果你还在用”所有人做一道题”当反垃圾方案,那你大概率是在用两位数的转化率损失,换一个对攻击者约等于零成本的门槛。维基百科的路径值得抄:先做无感判定,只对可疑会话出题。

如果你在做 agent:把宝押在”我的视觉模型能解题”上,是在赌一条正在关闭的路。真正的方向是可验证身份——签名、密钥、可追溯的调用来源。顺带一提,这也是评估 agent 工具时一个容易被忽略的维度:它能不能合规地上网,和它有多聪明是两件事。

十几年前,人工打码平台就已经把图像识别这层击穿了,千次成本压到几美分。所以验证码从来就不是靠”机器做不到”在防守,它靠的是抬高单次尝试的边际成本。

大模型做的事,是把这个成本再降一个数量级,顺便把延迟压到和人类反应时间相当——连”解得慢”这个信号也一并抹掉了。

图灵测试式的验证正在退场。接手的不是更难的图,是签名、凭证和信誉。而这套新体系带来的问题也已经能看见了:当上网需要一个可追溯的身份,谁来发这个身份、谁能撤销它,就成了下一轮要吵的事。
